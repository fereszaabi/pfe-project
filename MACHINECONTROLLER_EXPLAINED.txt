public function index(Request $request)
{
    $clientId = $request->user()->id;
    
    KEYWORD: "public"
    - VISIBILITY MODIFIER
    - ROLE: This method can be accessed from outside the class (via HTTP route)
    - OTHER OPTIONS: "private" (only inside class), "protected" (inside class + child classes)
    
    KEYWORD: "function"
    - ROLE: Defines a method (function inside a class)
    - NAME: "index" - Standard REST convention for "list all" operation
    - PARAMETERS: (Request $request) - Receives HTTP request data
    
    $clientId = $request->user()->id;
    - VARIABLE: "$clientId" - Stores the authenticated user's ID
    - KEYWORD: "$" - In PHP, all variables start with $
    - METHOD: "$request->user()" - Gets the logged-in user from request
    - PROPERTY: "->id" - Accesses the user's ID property (arrow operator for objects)
    - WHY: Security - only show machines belonging to THIS logged-in client

    $machines = Machine::where('id_client', $clientId)
                       ->select(['id', 'nom_poste', 'code_anydesk', 'created_at', 'updated_at'])
                       ->get();
    
    KEYWORD: "$machines" - Variable storing query results
    
    KEYWORD: "Machine::" - Static method call on Machine class
    - "::" is the scope resolution operator (static access)
    - "where()" - Database WHERE clause condition
    
    CHAIN METHOD: "->where('id_client', $clientId)"
    - -> is the object operator (method chaining)
    - Filters: Show only machines WHERE id_client = $clientId
    
    CHAIN METHOD: "->select(['id', 'nom_poste', 'code_anydesk', 'created_at', 'updated_at'])"
    - Specifies which database columns to retrieve
    - Optimization: Don't fetch unnecessary columns
    - [] is array notation in PHP
    
    CHAIN METHOD: "->get()"
    - Executes the query and returns all matching rows as a collection
    - Returns: Array of Machine objects

    return response()->json($machines);
    
    KEYWORD: "return" - Exit from function and send back a value
    KEYWORD: "response()" - Laravel helper that creates an HTTP response object
    METHOD: "->json($machines)" - Converts $machines to JSON format
    HTTP RESPONSE: Sends machine data back to client as JSON
    DEFAULT STATUS CODE: 200 (OK) - Indicates successful retrieval
}

5. METHOD 2: STORE (CREATE NEW MACHINE)
================================================================================

public function store(Request $request)
{
    $validated = $request->validate([
        'nom_poste' => 'required|string|max:255',
        'code_anydesk' => 'nullable|string|max:255',
    ]);

    KEYWORD: "public function store" - Standard REST convention for "create" operation
    PARAMETER: (Request $request) - Receives POST data from client
    
    $validated = $request->validate([...])
    
    KEYWORD: "validate()"
    - ROLE: Validates incoming data against rules
    - RETURNS: Validated data if passes, error response if fails
    - SECURITY: Prevents invalid/malicious data from being saved
    
    VALIDATION RULES (key => 'rules'):
    
    'nom_poste' => 'required|string|max:255'
        - 'required' - This field MUST be present and not empty
        - '|' (pipe) - Logical OR operator, separates multiple rules
        - 'string' - Value must be text, not number/boolean
        - 'max:255' - Maximum 255 characters
    
    'code_anydesk' => 'nullable|string|max:255'
        - 'nullable' - This field is OPTIONAL (can be null/empty)
        - 'string' - Must be text if provided
        - 'max:255' - Maximum 255 characters

    $clientId = $request->user()->id;
    - Gets the authenticated user's ID (same as index method)

    $machine = Machine::create([
        'id_client' => $clientId,
        'nom_poste' => $validated['nom_poste'],
        'code_anydesk' => $validated['code_anydesk'],
    ]);
    
    KEYWORD: "Machine::create()"
    - Laravel's Eloquent ORM (Object-Relational Mapping) method
    - ROLE: Creates a new record in 'machines' database table
    - PARAMETER: Array with column names as keys, values as data
    - AUTO-ASSIGNMENT: Fills $machine with the created record data
    - MASS ASSIGNMENT: Laravel assigns multiple fields at once
    - DB WRITES: Immediately saves to database, generates new ID
    
    ARRAY VALUES:
    - 'id_client' => $clientId - Links machine to current user (Foreign Key)
    - 'nom_poste' => $validated['nom_poste'] - Machine name (from validated input)
    - 'code_anydesk' => $validated['code_anydesk'] - AnyDesk code (optional)

    return response()->json($machine, 201);
    
    HTTP STATUS CODE: 201
    - MEANING: "Created" - Resource successfully created
    - STANDARD: REST convention for successful POST operations
    - RESPONSE BODY: The newly created machine object with ID
}

6. METHOD 3: UPDATE (MODIFY EXISTING MACHINE)
================================================================================

public function update(Request $request, Machine $machine)
{
    KEYWORD: "public function update" - Standard REST convention for "edit" operation
    PARAMETERS:
        - (Request $request) - Contains updated data from client
        - (Machine $machine) - Automatic route model binding (Laravel injects the machine)
                             - Laravel retrieves machine by ID from URL parameter
    
    $clientId = $request->user()->id;
    - Gets current user's ID for authorization check

    // Ensure the machine belongs to the authenticated client
    if ($machine->id_client !== $clientId) {
        return response()->json(['error' => 'Unauthorized'], 403);
    }
    
    KEYWORD: "if" - Conditional statement, executes code only if true
    KEYWORD: "!==" - Strict inequality operator
        - Checks if $machine's owner NOT EQUAL to current user
        - "!==" requires same type AND different value (strict comparison)
        - SECURITY CHECK: Prevent users from modifying other users' machines
    
    IF CONDITION FALSE (unauthorized):
        - return response()->json(['error' => 'Unauthorized'], 403);
        - HTTP STATUS CODE: 403 - "Forbidden" - User not permitted
        - RESPONSE: Error message in JSON format
        - STOPS EXECUTION: Function exits, doesn't reach update code

    $validated = $request->validate([
        'nom_poste' => 'sometimes|string|max:255',
        'code_anydesk' => 'nullable|string|max:255',
    ]);
    
    VALIDATION RULE: 'sometimes'
    - Different from 'required' and 'nullable'
    - MEANING: Field is optional
    - IF PROVIDED: Must pass other validation rules (string, max:255)
    - IF NOT PROVIDED: Validation passes anyway
    - USE CASE: PATCH/PUT requests where not all fields need updating

    $machine->update($validated);
    
    KEYWORD: "update()" - Eloquent ORM method
    - ROLE: Updates existing database record with new values
    - PARAMETER: Array with fields to update
    - DB OPERATION: Executes UPDATE query on database
    - SMART: Only updates fields that were provided (from validation)

    return response()->json($machine);
    
    HTTP STATUS CODE: 200 (default)
    - MEANING: "OK" - Update successful
    - RESPONSE: Updated machine object with new values
}

7. METHOD 4: DESTROY (DELETE MACHINE)
================================================================================

public function destroy(Request $request, Machine $machine)
{
    KEYWORD: "public function destroy" - Standard REST convention for "delete" operation
    PARAMETERS: Same as update method
        - (Request $request) - HTTP request data
        - (Machine $machine) - Machine to delete (injected by Laravel)

    $clientId = $request->user()->id;
    - Gets current user's ID

    // Ensure the machine belongs to the authenticated client
    if ($machine->id_client !== $clientId) {
        return response()->json(['error' => 'Unauthorized'], 403);
    }
    
    AUTHORIZATION CHECK: Same as update method
    - Prevents users from deleting other users' machines
    - Returns 403 Forbidden if not owner

    $machine->delete();
    
    KEYWORD: "delete()" - Eloquent ORM method
    - ROLE: Deletes the record from database
    - DB OPERATION: Executes DELETE query on 'machines' table
    - REMOVES: The entire machine record and all its data
    - IRREVERSIBLE: Cannot be undone (unless backed up)

    return response()->json(['message' => 'Machine deleted successfully']);
    
    RESPONSE: Success message confirming deletion
    HTTP STATUS CODE: 200 (default)
    - MEANING: "OK" - Deletion successful
    - RESPONSE FORMAT: Simple JSON with confirmation message
}

10. REST API CONVENTIONS
================================================================================

HTTP Methods Used:
    - GET (index) - Retrieve data, safe, no side effects
    - POST (store) - Create new resource, changes server state
    - PATCH (update) - Partially update existing resource
    - DELETE (destroy) - Remove resource

HTTP Status Codes Used:
    - 200 OK - Request successful, return data
    - 201 Created - Resource successfully created
    - 403 Forbidden - User not authorized to perform action
    - (404 Not Found - Implicit when machine doesn't exist)

URI Endpoints (based on Laravel routing):
    - GET /api/client/machines - index (list all)
    - POST /api/client/machines - store (create new)
    - PATCH /api/client/machines/{id} - update (edit specific)
    - DELETE /api/client/machines/{id} - destroy (delete specific)

11. SECURITY FEATURES IN THIS CONTROLLER
================================================================================

1. Authentication:
    - "$request->user()" - Requires logged-in user
    - If no user logged in, request fails before reaching controller
    - Laravel middleware handles this

2. Authorization:
    - if ($machine->id_client !== $clientId)
    - Checks user owns the machine before update/delete
    - Prevents users from modifying other users' data
    - Returns 403 Forbidden if unauthorized

3. Input Validation:
    - $request->validate([...])
    - All input checked before saving to database
    - Prevents SQL injection, invalid data, oversized strings
    - Returns validation errors if rules violated

4. Mass Assignment Protection:
    - Machine::create() with specific fields
    - Only allows specified columns to be set
    - Prevents users from setting unauthorized fields (like id)

12. DATABASE INTERACTION FLOW
================================================================================

EXAMPLE: Client creates a new machine

1. Frontend sends: POST /api/client/machines
   {
     "nom_poste": "Server-02",
     "code_anydesk": "ABC123456"
   }

2. Laravel routes to: MachineController@store

3. Controller executes:
   - Gets user ID from request: $clientId = 1
   - Validates input against rules
   - Creates record: Machine::create([...])
   - Laravel generates INSERT SQL:
     INSERT INTO machines (id_client, nom_poste, code_anydesk, created_at, updated_at)
     VALUES (1, 'Server-02', 'ABC123456', NOW(), NOW())
   - Database executes query
   - New record created with auto-generated ID (e.g., 5)
   
4. Returns: HTTP 201 + JSON response with new machine data

5. Frontend receives and displays new machine to user

13. KEY CONCEPTS SUMMARY
================================================================================

Object-Oriented Programming (OOP):
    - Classes group related functionality
    - Methods perform actions on objects
    - Inheritance (extends) reuses code from parent

Eloquent ORM:
    - Object-Relational Mapping
    - Write PHP instead of SQL
    - Automatic table/column mapping
    - Built-in security features

RESTful API:
    - Standard way to design web APIs
    - Uses HTTP methods + URIs for operations
    - Status codes convey operation result
    - JSON for data format

Route Model Binding:
    - Laravel automatically injects Machine object
    - Instead of: $machine = Machine::find($id)
    - Just receive: Machine $machine as parameter

Method Chaining:
    - Multiple methods called in sequence (-> -> ->)
    - Each method returns object for next method call
    - Makes code readable and concise

14. OVERALL PURPOSE
================================================================================

This MachineController is a REST API controller that manages client machines.

Responsibilities:
    1. INDEX method - List all machines for logged-in client
    2. STORE method - Create new machine, link to client
    3. UPDATE method - Edit machine details (only if client owns it)
    4. DESTROY method - Delete machine (only if client owns it)

Security:
    - All operations require authentication (logged-in user)
    - All operations check ownership before access/modify/delete
    - All input validated to prevent invalid data

Database:
    - Writes to 'machines' table
    - Links machines to clients via id_client foreign key
    - Each machine has: id, id_client, nom_poste, code_anydesk, timestamps

Usage:
    - Frontend (React) makes HTTP requests to these endpoints
    - Controller processes requests and returns JSON
    - Frontend displays machines to user
